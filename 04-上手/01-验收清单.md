# 验收清单（H3 版）

> 12 项。每项给命令与期望值。**全过 + 输出留存**，才算这条线是通的。
> **在项目根执行**（含 `magic/`）；脚本在 `code/`。命令用 Bash 语法；PowerShell 请换成等价写法。

---

## A. 基础（一次性，5 项）

### A1 配置生效

```bash
python code/run_twopass_auto.py --status
```

| 期望 | 值 |
|---|---|
| 链型 | `legacy` |
| 抽卡分辨率 | `704x384` |
| 二采分辨率 | `1280x704` |
| 尾帧帧数 | `24` |
| 交叉淡化 | `0.2` |
| H3 状态 | online |

任何一项不符 → 先查 `code/twopass_spec.json`，不要在命令行临时覆盖。

### A2 源 → 派生 链一致

```bash
python code/chain_check.py check --shot <镜> \
  --md magic/docs/prompts/<act>/<shot>.md \
  --episodes magic/configs/episodes.json \
  --template code/api_workflow_twopass_legacy_<shot>_ref2v_draw_384p10.json
```

**期望**：退出码 0，三层摘要一致（md / episodes / 模板）。

**不一致**：运行 `reconcile`（同参数）重建；若提示模板被手改，先确认不是别人的在途修改。

### A3 资产双份一致

```bash
python code/sync_assets.py --check
```

**期望**：无差异输出。

**为什么**：H3 读的是 input 目录副本，项目里的图改了没同步 = 跑旧图。

### A4 接力帧数精确

```bash
ffprobe -v error -count_frames -select_streams v:0 \
  -show_entries stream=nb_read_frames -of csv=p=0 \
  magic/assets/shots/shot_battle/<上镜>_tail24.mp4
```

**期望**：`24`（等于 spec 的 `video_ref_frames`，不是「≥5」）。

**同时**：截取必须重编码。用 `relay.py` 生成，不要手敲 ffmpeg 加 `-c copy`。

### A5 门禁度量有区分度

```bash
# 取产物第一帧，自比
ffmpeg -y -v error -i <产物.mp4> -vf "select=eq(n\,0)" -frames:v 1 _first.png
python code/quality_gate.py <产物.mp4> --ref _first.png
```

**期望**：像素差 ≈ 0。

若「自比」都得到明显非零值 → 度量或取帧有问题，门禁不可信。

## B. 单镜（每镜，4 项）

### B1 首帧锁定

```bash
python code/quality_gate.py <二采产物.mp4> \
  --ref magic/assets/shots/shot_battle/<上镜>_tail_frame.png
```

| 像素差 | 结论 |
|---|---|
| < 15 | 优 |
| 15–25 | 及格 |
| 25–50 | 重抽，或检查首帧描述漏项 |
| ≥ 50 | 设计矛盾（跳切镜却锁帧）或走样，先查设计 |

硬切镜省略 `--ref`。

### B2 音频

```bash
python code/audio_check.py <二采产物.mp4>
```

| 判定 | 处理 |
|---|---|
| `OK` | 通过 |
| `CLIP破音` | 淘汰，不可修复 |
| `台词弱` | 看台词窗 RMS；是否被环境声盖住，或需重抽 |

**注意**：判定看 `peak` 列；表里的 `Peak count` 若出现是通道数，不是削波次数。

### B3 时长容差

```bash
ffprobe -v error -show_entries format=duration -of csv=p=0 <产物.mp4>
```

**期望**：与 md 的 `duration` 相差 ≤ 5 帧（0.2s）。

**为什么不是 1 帧**：模板把帧数补齐到 `max(5, round(d×24)) + (5 − x%17)%17`。
实测：请求 5.0s → 124 帧（5.167s）；10.0s → 243 帧（10.125s）；15.0s → 362 帧（15.083s）。
**不要用 0.05s 硬阈值**——它会把正常产物判成失败。

### B4 接力产物齐全

```bash
ls -l magic/assets/shots/shot_battle/<镜>_tail_frame.png \
      magic/assets/shots/shot_battle/<镜>_tail24.mp4
```

**期望**：
- 两个文件都存在；
- 尾帧图 = 尾段的最后一帧（可用 `quality_gate` 反向自比 ≈ 0 验证）；
- 自动同步到 H3 input，日志里有 md5。

## C. 全片（交付前，3 项）

### C1 总时长 = 逐镜实测累加

```bash
# 每个镜头的时长
for f in <镜1>.mp4 <镜2>.mp4 ...; do ffprobe -v error -show_entries format=duration -of csv=p=0 "$f"; done
# 成片时长
ffprobe -v error -show_entries format=duration -of csv=p=0 <成片.mp4>
```

**期望**：成片时长 ≈ `Σ(每镜实测) - 0.2 × (镜数-1)`，误差 < 0.2s。

**不要用「镜数 × 单镜时长」**：H3 产物时长不恒定。

### C2 交付规格与三版本

```bash
ffprobe -v error -select_streams v:0 -show_entries stream=width,height,r_frame_rate -of csv=p=0 <成片.mp4>
ffmpeg -nostats -i <成片.mp4> -filter_complex ebur128 -f null - 2>&1 | tail -12
```

| 项 | 期望 |
|---|---|
| 分辨率 | 1920×1080 |
| 帧率 | 24 |
| 响度 | 统一（如 -16 LUFS），无削波 |
| 审片版 | 硬切，无淡化 |
| 标注版 | 每镜有编号小标 |
| 交付版 | 淡化 + 色彩匹配 + 统一响度 |

### C3 复现性已确认

同一 spec、同一种子再跑一次，比较产物。

| 结果 | 结论 |
|---|---|
| 一致（或度量一致） | 可以做严格 A/B |
| 不一致 | 正常；后续对照改为多次采样比较，并在记录里写明 |

**不通过不是缺陷**，但「不知道」是。

## 一条纪律

> **验收失败时，修流程，不修判据。**

阈值（15/25/50、24 帧、0.2s）都是从真实事故来的。要调，先写清楚：为什么调、用什么样本标定、调完有没有回归。
