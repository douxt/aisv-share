# 已知限制

> 这些不是「待优化项」，是在当前栈上**做不了或代价很高**的事。
> 卡住时先对照这张表，再决定是绕过、降级，还是换方案。

---

## 硬件与实例

| 限制 | 表现 | 应对 |
|---|---|---|
| **只能单实例** | H3 与资产实例同时开 → 显存打满，系统卡死 | 二选一；切换前先停另一个（精确 PID） |
| 16GB 是下限 | 高分辨率长镜 OOM | 抽卡 704×384；二采 1280×704；1080p 只在超分阶段 |
| 长时运行会累积 | 内存缓慢上涨，数小时后崩溃 | 保留 RAM 守护；异常时人工重启，不要硬撑 |
| 整段超分会爆内存 | 一次载入全部帧 = 数十 GB | 单镜层超分，分批 + 每批清缓存 |

## 时长与运动

| 限制 | 表现 | 应对 |
|---|---|---|
| 15 秒镜容易尾段花屏 | 最后几帧坏、闪烁 | >10 秒镜**禁用** sage 加速；严重时裁掉尾部 |
| 10 秒是主力档 | 10 秒内 2–4 拍最稳 | 想塞更多事件 → 拆镜，不要加时长 |
| 快速甩镜不可控 | 糊成一团 | 只在转场用一帧，不做连续运动 |
| 环绕超过约 90° | 露出未建模的背面 | 半圈以内 |
| 连续跟拍易出画 | 主体跑出画面 | 写清终点；或改成固定机位 + 主体移动 |

---

## 一致性

| 限制 | 表现 | 应对 |
|---|---|---|
| 参考图超过 5 张会串味 | 配角长得像主角、武器换手 | 多人镜只锚 2–3 个主要角色 |
| 同框超过 3 个主要角色 | 特征互相渗透 | 群像镜用「前排锚定 + 后排纯文字」 |
| 角色资产来源不统一 | 同一角色跨镜不像 | 全部视角用同一套流程重生成，包括正面 |
| 参考视频不等于「只借运动」 | 它传的是像素，会带外观 | 运动参考用短尾段；外观靠首帧与文字 |

---

## 声音

| 限制 | 表现 | 应对 |
|---|---|---|
| 音色参考只锚音色 | 内容可能被模仿 | 提示词写明「仅作音色参考」；参考内容与台词不同 |
| 参考音频开头的微弱声响 | 视频开头多一个音节 | 参考音频前置 0.5 秒静音 |
| 二采音量偏低 | 比抽卡低 5–8 dB | 拼接时全片统一响度（loudnorm），不要逐镜修 |
| 口型精度有限 | 特写对白会穿帮 | 用背身/远景/遮挡；或后期配音 + 调整构图 |
| 唱歌需要旋律匹配 | 新词配旧曲 = 怪 | 歌词与旋律参考同词/同音步；唱速 2–2.5 字/秒 |
| 削波不可逆 | 峰值 > 0dB | 抽卡后直接检测并淘汰 |

## 文字与画面

| 限制 | 表现 | 应对 |
|---|---|---|
| 场景内中文不可靠 | 糊、错字、乱码 | 换成无文字元素（频谱屏/光影）；需要文字用后期 PIL 贴 |
| 精确数值/刻度不可信 | 表盘、路牌、数字乱写 | 避免近景特写 |
| 手指、小道具易变形 | 数手指、道具融合 | 避免手部大特写；用合成图绑定道具 |
| 特效参考图会被当布景 | 特效固定原地不动 | 特效纯 prompt；写明「随主体移动」 |
| 灰蒙/低对比 | 画面发闷 | 明写光源方向 + 调色串 |

## 工程与环境

| 限制 | 表现 | 应对 |
|---|---|---|
| Windows 控制台编码 | 中文输出乱码/崩溃 | 脚本显式设置 UTF-8；读写都指定编码 |
| 目录 junction 被拒 | H3 读不到素材 | 用真实目录副本 + `sync_assets.py` |
| 产物时长不恒定 | 拼接总时长算错 | 逐镜实测累加，禁止乘法 |
| 产物缓存/命名 | 改稿后看到旧片 | 改稿换种子；比较 mtime |
| 抽卡产物 ≠ 交付分辨率 | 复用「产物存在」检查会永远失败 | 抽卡与交付分开校验 |
| 自动流程不会识别设计矛盾 | 反复重试烧 GPU | 同因失败 3 次即停，人工查设计 |
| 脚本仅 Windows | PowerShell / netstat / 盘符路径 | 非 Windows 需自行改写进程与路径相关代码 |

## 当前明确做不了

| 事项 | 说明 |
|---|---|
| 复杂多人动作编排 | 超过 3 人同时交互，身份与空间都容易崩 |
| 精确口型同步 | 只能做到「大致对上」 |
| 画面内可读的中文 | 一律后期贴 |
| 单一长镜连续叙事 | 模型对长镜的机位控制弱；拆段 + 接缝更可靠 |
| 完全无人值守 | 设计矛盾、审美判断仍需要人；自动只能覆盖机械环节 |

---

## 怎么用这张表

1. **立项时**：把「做不了」的条目对照剧本，能改的改，改不了的设计规避；
2. **卡住时**：先在这张表里找症状，再去看 `03-stack/故障排查.md` 的具体命令；
3. **新增时**：每发现一条新边界，追加一行——判据是**下次能不能三十秒内判断「这是边界还是 bug」**。
