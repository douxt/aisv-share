# 一小时走查：跑出第一个镜头

> 面向已装好 H3 + ComfyUI 的读者。目标：从零到一个可验收、可接力的 10 秒镜头。
> **在项目根执行**（项目根包含 `magic/`）；脚本在 `code/`。示例假设项目根 = 当前目录，
> 否则先设 `AISV_PROJECT_ROOT=<你的项目根>`。目录约定见 `code/README.md`。

---

## 0. 前置检查（5 分钟）

### 0.1 只开一个实例

H3（8188）与资产实例（8189）**不能同时跑**——每个工作流占满显存，双开会导致系统卡死。

```bash
netstat -ano | findstr :8188
```

**期望**：只有 H3 在跑。要跑资产就先停 H3，反之亦然。

### 0.2 H3 启动参数

```bash
# 检查当前进程命令行是否带这两个参数
wmic process where "name='python.exe'" get commandline | findstr /i "cache-ram disable-pinned"
```

| 镜头时长 | 必须带 |
|---|---|
| 所有 | `--disable-pinned-memory --cache-ram 16` |
| ≤10 秒 | **必须带** `--use-sage-attention`（runner 会校验；缺了直接中止） |
| >10 秒 | **禁止** sage（长序列尾段会花屏） |

### 0.3 配置自检

```bash
python code/run_twopass_auto.py --status
```

**期望**：输出当前配置（链型 / 抽卡分辨率 / 二采分辨率 / 尾帧帧数 / 交叉淡化时长）、当前镜、产物存在性、H3 是否在线。

**这里显示的分辨率必须是 `704x384`（抽卡）与 `1280x704`（二采）**，否则先查 `code/twopass_spec.json`。

> 还没 build 过模板时，`--status` 会提示「模板/产物不可用」，这是正常的；继续第 3 步即可。

---

## 1. 写镜头源文档（15 分钟）

路径：`magic/docs/prompts/<act>/<shot>.md`

```markdown
---
shot: act1_1a
act: act_1
order: 1
duration: 10.0
aspect_ratio: "16:9 (Widescreen)"
images: [magic/assets/characters/hero/front.png, magic/assets/envs/stage_final.png]
video_ref: ""
audio: [magic/assets/voices/hero.mp3]
deps: []
scene_inherit: "无上镜（首镜）：舞台空场 → 主角从台侧入画站定 → 缓推近"
---

# act_1 镜 1a — 开场

## 修改记录

- v1：初版。

```text
subject_definitions:
...
summary:
...
retention_analysis:
...
detailed_description:
A quiet stage with cool violet key light, teal shadows, shallow depth of field.
At 00:00.000 the empty stage holds, haze drifting through the beams.
At 00:02.000 <Subject 1> steps in from the right edge and stops at stage center.

```

**必须齐的字段**：`shot / duration / images / video_ref / audio / scene_inherit` + 六个文本段。
衔接镜的 `images` 第一位必须是上一镜尾帧图，`video_ref` 指向上镜 `_tail24.mp4`。

---

## 2. 同步资产（1 分钟）

```bash
python code/sync_assets.py --check
python code/sync_assets.py --sync
```

**期望**：`--check` 列出差异；`--sync` 后差异归零。

**为什么**：H3 只读自己 input 目录的副本；项目里的改动不同步 = 跑的是旧图。

---

## 3. 生成模板（1 分钟）

```bash
python code/build_episodes.py --shots act1_1a
python code/build_twopass.py --shot act1_1a
```

**期望**：
- 第一条：`episodes.json` 里出现 `act1_1a`，且与 md 一致；
- 第二条：`code/` 下出现 `api_workflow_twopass_legacy_act1_1a_ref2v_draw_384p10.json` 与 `..._ref2v_384p10.json`。

**报错 `drift detected`**：说明有人手改过派生物。用 `--force` 前先确认不是别人的在途修改。

---

## 4. 抽卡（15–25 分钟）

编辑 `code/run_twopass_auto.py` 顶部：

```python
RUNS = [
    ("ref2v_draw_384p10", 10001),
    ("ref2v_draw_384p10", 10002),
    ("ref2v_draw_384p10", 10003),
    ("ref2v_draw_384p10", 10004),
]
SHOT = "act1_1a"
```

> 确认 `SHOT` 与 `RUNS` 都是你的镜头；`--status` 可复查当前批。

```bash
python code/run_twopass_auto.py
```

**期望**：每发约 3–6 分钟，日志写到 `code/twopass_auto_log.jsonl`；产物在 ComfyUI 的 `output/magic/` 下，文件名含 `run<seed>`。

**注意**：
- 改过 md 必须换新种子域，否则可能读到旧产物；
- 跑批前 preflight 会检查模板与 spec 是否一致，不一致直接中止——不要绕过。

---

## 5. 审帧选卡（10 分钟）

```bash
python code/relay.py --shot act1_1a --preview --only-seeds 10001 10002 10003 10004
```

**期望**：`magic/preview/act1_1a/` 下每个种子 4 张图（1.5s / 4s / 6.5s / 9s）。

逐张看：
1. 首帧对不对（衔接镜看像素差，见下一步的门禁）；
2. 人数、身份、道具对不对；
3. 动作是否完成；
4. 有无闪烁/变形/破音。

**选出 1 条**，记下它的种子。

---

## 6. 二采（12–25 分钟）

把 RUNS 改成选中的种子，变体换成二采：

```python
RUNS = [
    ("ref2v_384p10", 10003),
]
```

```bash
python code/run_twopass_auto.py
```

**期望**：产物名为 `..._ref2v_384p10_run10003.mp4`，分辨率 1280×704。

---

## 7. 门禁（1 分钟）

```bash
# 首镜是硬切（不锁帧）：省略 --ref
python code/quality_gate.py <产物.mp4>

# 衔接镜才需要：--ref 指向上镜的尾帧图（由第 8 步生成）
python code/quality_gate.py <产物.mp4> --ref magic/assets/shots/shot_battle/<上镜>_tail_frame.png
```

**期望**：

| 首帧平均像素差 | 结论 |
|---|---|
| < 15 | 优 |
| 15–25 | 及格 |
| 25–50 | 重抽或检查首帧描述 |
| ≥ 50 | 设计矛盾或走样，先查设计 |

**首镜/硬切镜不要传 `--ref`**——它的尾帧要到第 8 步才生成；传了会报「锁帧 ref 缺失」。

**为什么用二采产物做门禁**：抽卡是低分辨率，二采才是交付版本；锁帧质量要在交付版本上量。

---

## 8. 接力（1 分钟）

```bash
python code/relay.py --shot act1_1a
```

**期望**：
- `magic/assets/shots/shot_battle/act1_1a_tail_frame.png`（尾帧）
- `..._act1_1a_tail24.mp4`（24 帧尾段，**重编码**）
- 自动同步到 H3 input，并输出 md5

**只有这一步做完，下一镜才能写硬衔接。**

---

## 9. 接缝（2 分钟）

**先做第二镜**：重复第 1–8 步，得到第二个镜头的产物。接缝需要两个镜头。

```bash
python code/seam_join.py --a <镜A.mp4> --b <镜B.mp4> --out magic/output/seam_ab.mp4
```

**期望**：0.2 秒交叉淡化 + 音频交叉；输出分辨率与前两镜一致。

**审片时不要用带淡化的版本**——淡化会盖住接缝问题。

---

## 10. 全片拼接与超分（后台 45 分钟 / 25 镜）

```bash
python code/join_clips.py <镜1.mp4> <镜2.mp4> ... --out <成片_720p.mp4>
python code/upscale_batch.py --out <成片_1080p.mp4> --clips <镜1.mp4> <镜2.mp4> ...
```

**期望**：
- 总时长 = 逐镜实测累加（不是乘法）；
- 超分在单镜层做，输出 1920×1080；
- 时长、帧率与输入一致。

---

## 时间与失败对照

| 步骤 | 首次 | 失败时先看 |
|---|---|---|
| 前置检查 | 5 min | `--status` 的 H3 状态与配置摘要 |
| 写 md | 15 min | 六段是否齐、时间戳是否超时长 |
| 模板构建 | 2 min | drift 提示 → 有没有手改派生物 |
| 抽卡 | 15–25 min | preflight 中止信息 / H3 是否在线 |
| 审帧 | 10 min | 首帧、人数、道具、破音 |
| 二采 | 12–25 min | 同上 + 产物分辨率 |
| 门禁 | 1 min | 像素差数值 |
| 接力 | 1 min | 帧数是否 24、是否重编码 |
| 接缝 | 2 min | 色调、卡顿、人物位置 |

**首次超过 3 小时**：不要继续硬跑。按 `02-已知限制.md` 对照，卡在哪一条就处理哪一条。
