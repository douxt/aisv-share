# 提示词检查链：在花掉 GPU 之前把错误拦住

> 方法层第 5 篇。讲「一份提示词写完之后、按下生成之前，应该过哪几道检查」。
> **基线：MiniMax H3 + 六段式**；检查项的实现见 `03-stack/提示词技能.md` 与 `templates/skill/`。

---

## 1. 为什么单独讲这个

流程里最便宜的阶段是写提示词，最贵的阶段是生成。但两者的距离只有一次点击。

现实是：**大部分废片不是模型不行，是提示词带着能查出来的毛病进了 GPU。**

能查出来的毛病分两类：
- **确定性的**：字段缺失、时间戳超过时长、参考图超上限、写了禁用词——这些不该靠人眼；
- **需要理解的**：描述与参考图不一致、动作在物理上不成立——这些可以半自动。

这一篇讲的，就是把这两类分开，各自用对的办法。

---

## 2. 四条原则

| 原则 | 说明 |
|---|---|
| **规则外置** | 规则写在文件里，每次生成都读，不靠记忆或「凭感觉」 |
| **机械先于语义** | 便宜、确定、零误判的先跑；语义检查放后面 |
| **语义只报警** | 视觉模型的判断不可靠，除非是「锁帧主体状态」这种窄问题，否则只能作警告 |
| **检查器必须有牙** | 没被已知坏样本击穿过的检查器，等于没装 |

第四条最容易被忽略。我们见过检查器「全部通过」而片子明显是坏的——因为它只查「关键词有没有」，不查「动作用词和图的状态是否矛盾」。

---

## 3. 九层检查

按执行顺序。注意：**顺序本身是成本控制**——便宜的排在前面，错得越早越省钱。

| 层 | 查什么 | 判据类型 | 误报风险 | 不过怎么办 |
|---|---|---|---|---|
| **L0 输入** | 参考图/音频/视频文件存在；时长字段与分镜表一致 | 机械 | 无 | 中止 |
| **L1 结构** | 段落顺序、标签闭合、每段必填、时间戳单调且不超过时长 | 机械 | 无 | 中止 |
| **L2 语言反模式** | 负面词、步数、空泛形容词、摄影术语误用、禁词表 | 机械 | 低 | 中止 |
| **L3 预算与引用** | 参考图数量 ≤ 上限；锁帧图在首位；每图职责唯一；标签一致 | 机械 | 低 | 中止 |
| **L4 跨文档一致** | 上游尾帧的设计 vs 下游复述；场景状态继承是否写了 | 机械 | 中（需解析自然语言） | 中止 |
| **L5 动作可执行** | 位移有起点/路径/终点；落位有锚；事件间隔 ≥0.5s；特效有去向 | 规则 | 中 | ERROR 中止 / WARN 放行 |
| **L6 语义一致** | 参考图里有什么 vs 描述写了什么（尤其锁帧首帧） | 视觉模型 | **高** | 警告为主；锁帧主体矛盾才中止 |
| **L7 空间断言** | 机位、站位、路径能否被画出来 | 视觉模型（断言清单） | 中 | 警告 |
| **L8 人闸** | 设计意图有没有被表达；好不好看 | 人 | — | 人工决定 |

### 为什么 L6/L7 用「断言清单」而不是「自由审查」

自由问「这段描述有没有空间矛盾」，模型会倾向于回答「看起来没问题」。
把它改成「逐条判断以下 8 条断言：成立 / 不成立 / 图中不存在」——判定质量明显提升。

我们的实测：自由审查的召回率很低，改成结构化断言 + 强制选项后才有生产价值。

> **通用推论**：任何「让模型找问题」的检查，都要把问题**枚举成清单**，并禁止「可能 / 也许 / 大概」这类选项。

### 为什么 L6 只能报警

同一张远景图，视觉模型对人物姿态的三次描述可能三次不同。
所以它适合回答**窄问题**（「图中人物是站着还是蹲着」），不适合回答**开放问题**（「这个描述准不准」）。

分级做法：
- 近景 + 主体动作矛盾 → 中止；
- 远景 + 姿态/表情不符 → 警告，交给像素差门禁兜底。

## 4. 检查器的「有牙」验证

每个检查器上线前，跑两组样本：

| 样本 | 要求 |
|---|---|
| 已知好提示词（3–5 份，实际生成过好片的） | 必须**全部通过** |
| 已知坏提示词（每种毛病一份） | 必须**全部拦住，且指出正确的毛病** |

第二组要特别小心：如果检查器报了错但报的是别的原因，说明它没有真正理解——只是碰巧没过。

**回归**：规则一改，两组都重跑。改了检查器不回归 = 引入静默退化。

---

## 5. 误报的代价

检查器误报一次，人就会开始习惯性忽略它；忽略三次，它就等于被关掉了。

所以：
- 每条规则都要能指出**具体位置**（第几段、哪一句、哪个词）；
- 规则要标「这条为什么危险」，让人能判断是否该忽略；
- 宁可少一条规则，不要多一条噪声。

---

## 6. 与闸门的关系

检查链不是闸门。区别：

| | 检查链 | 闸门 G2 |
|---|---|---|
| 执行者 | 机器 | 人 |
| 判据 | 确定的、可枚举的 | 意图、节奏、可看性 |
| 失败处理 | 中止或警告 | 返工或放行 |

**顺序**：先过检查链，再进 G2。让人只看机器看不出来的东西，而不是让人替机器找错别字。

---

## 7. 停止规则

同一份提示词，连续 3 次因**同一个原因**被拦：

> **不要再改措辞。停下来，怀疑设计。**

真实的失败三种：措辞问题、设计问题、栈能力问题。检查器只能告诉你是哪一层，不能告诉你是哪一种。连续同因 = 后两种的概率远大于第一种。

---

## 8. 一页速查

```
L0 文件在不在
L1 结构对不对
L2 有没有禁用写法
L3 参考图预算超没超、锁帧图在不在首位
L4 和上一镜对不对得上
L5 动作画不画得出来
L6 描述和图对不对得上（只报警）
L7 空间断言逐条过（只报警）
L8 人看一遍
        ↓
      生成
```
