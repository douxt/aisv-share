# 落地档位：L0 手工 → L3 全自动

> 落地层第 1 篇。
> 目的：让你**明确选一档**，而不是「看情况」。每档写清楚：要写多少东西、能验收什么、什么时候该升级。

---

## 0. 先破一个误解

自动化不是「好」，手工不是「差」。它们是不同阶段的答案。

| 你在做什么 | 正确档位 |
|---|---|
| 验证模型能不能做出你要的效果 | **L0** |
| 做完一集，想少点重复劳动 | **L1** |
| 要连着做多集，不能每次靠记忆 | **L2** |
| 完全无人值守、长时间批跑 | **L3** |

**最常见的错误**：在「还不知道自己要什么」的时候上 L3。结果是自动化帮你高效地生产错东西。

---

## 1. 四档总表

| | L0 手工 | L1 脚本化 | L2 门禁化 | L3 全自动 |
|---|---|---|---|---|
| **你怎么干活** | 界面点、手动截、剪辑软件拼 | 命令行跑生成/截取/拼接 | 脚本 + 自动检查 | 状态机自己跑，人只看报告 |
| **适配器函数** | 0（人工对应） | 3：generate / extract_tail / join_clips | 5：+ measure / compare_frames | 6：+ upscale，外加编排 |
| **配置** | 散在脑子里 | spec 文件 | spec + 预检 + sidecar | 同左 + 批次配置 |
| **能验收** | 只能人看 | `05` 的 A1/A2/A5 | `05` 全部 12 项 | 12 项 + 恢复/暂停/报警 |
| **每镜耗时** | 高（含切换与抄参数） | 中 | 中 | 低（人只在闸门出现） |
| **适合** | 探索、试拍 | 单人做一集 | 反复做、要可复现 | 多集、长时批跑 |
| **典型风险** | 漏参数、版本混 | 参数漂移 | 检查器误报被忽略 | 系统性错误无人察觉 |

## 2. L0 手工

### 你要做什么

| 契约函数 | 手工对应 |
|---|---|
| generate | 界面填参数、提交、记种子 |
| extract_tail | 剪辑软件取最后一秒，导出图片 + 视频 |
| measure | 播放器/属性/探针工具 |
| compare_frames | 并排看（**注意：15–25 的差别人眼不可靠**） |
| join_clips | 剪辑软件接，加短交叉淡化 |
| upscale | 放大工具 |

### 必须坚持的三件事

1. **记种子**。写在分镜表旁边。没有种子就无法复现、无法对照。
2. **一次只改一处**。手工作坊最容易「顺手都改一下」，然后不知道哪个起的作用。
3. **写下每次修改**。格式：`v2：把唱段从 2.5s 扩到 4s → 节奏正常，结尾空 1.5s`。

### 什么时候必须升级

出现任意两条：

- 同一个参数抄错两次以上；
- 开始分不清哪条片子是哪版生成的；
- 单镜的重复操作超过 10 分钟。

## 3. L1 脚本化

### 最小实现

三个函数 + 一个 spec：

```python
generate(req) -> result          # 提交与轮询
extract_tail(video, n) -> tail   # 重编码截取
join_clips(clips, xfade) -> result
```

### 这一档买到什么

| 收益 | 说明 |
|---|---|
| 参数不再手抄 | 分辨率/时长/种子只写在一个地方 |
| 截取变可靠 | 帧数精确、自动重编码 |
| 拼接不再算错 | 逐镜实测累加 |
| 产物命名统一 | 便于归档与追溯 |

### 还没解决

- 产物对不对，没人自动检查；
- 改了提示词忘记换种子，仍然可能读到旧片；
- 跨镜一致性仍靠人。

### 验收

跑 `05-验收清单.md` 的 A1、A2、A5 三项。其余项手工记录。

---

## 4. L2 门禁化（推荐长期停留的档位）

### 增加什么

| 项 | 作用 |
|---|---|
| `measure` | 一切校验的地基：分辨率、时长、帧率、音频峰值 |
| `compare_frames` | 首帧锁定的机械判据 |
| 预检 | 跑之前：spec 与能力是否自洽、参考图是否超限 |
| 产物校验 | 跑之后：实测规格 == spec，不是「不小于」 |
| sidecar | 每个产物记录种子 / 提示词哈希 / 配置版本 |
| 阈值表 | 15 / 25 / 50，放在 spec 里而不是代码里 |

### 为什么这一档值得多花两三天

因为它把「我记得」换成「机器检查」。我们最贵的几次事故全部属于这一类：

- 参数在三个地方漂移 → 跑了一整轮才发现跑的不是定案配置；
- 改了稿没换种子 → 看到的是旧片；
- 拼接用了乘法 → 成片少 27 秒。

这些在 L2 都是自动拦。

### 验收

`05-验收清单.md` **全部 12 项**。这是「接上了」的正式标准。

## 5. L3 全自动

### 增加什么

```
状态机：接力 → 预处理 → 抽卡 → 审帧 → 选卡 → 精修 → 门禁 → 接力 → … → 拼接 → 超分
```

| 机制 | 为什么必须有 |
|---|---|
| **幂等** | 每阶段先查产物，存在就跳过。崩溃后能续 |
| **范围唯一控制点** | 改批次配置决定跑哪几镜，不改代码 |
| **审计日志** | 每次决策一行，供事后复盘与告警 |
| **人工暂停是一等状态** | 暂停标记优先于自动恢复 |
| **同因失败聚类** | 同一原因连续 N 次 → 停止并报警 |
| **资源守卫** | 内存/显存阈值，超了先释放再继续 |

### L3 不解决什么

- 审美判断（仍要人）；
- 设计矛盾（自动流程只会反复重试，浪费更高效）；
- 判据不清的环节（自动只会把模糊放大）。

### 验收

12 项之外，加三项**故障演练**：

| 演练 | 期望 |
|---|---|
| 跑到一半杀掉进程 | 重启后从断点续跑，不重做已完成镜 |
| 人工暂停 | 不被自动恢复拉起 |
| 注入同类失败 3 次 | 停止并报警，不继续烧 GPU |

**没做过故障演练的 L3，不算 L3。**

## 6. 投入估算

> 粗估，按一人、已有可用模型计算。

| 档位 | 首次投入 | 持续维护 | 何时回本 |
|---|---|---|---|
| L0 | 0 | 高（每镜手工） | — |
| L1 | 1–2 天 | 低 | 一集（约 25 镜）就回本 |
| L2 | 再加 2–3 天 | 中 | 第二集开始明显 |
| L3 | 再加 3–5 天 | 中高 | 三集以上，或需要无人值守 |

**注意**：L3 的维护成本经常被低估——模型升级、API 变更、节点变动，都会让编排层需要改。

---

## 7. 分工：一个人 vs 两个人

| 角色 | L0 | L1 | L2 | L3 |
|---|---|---|---|---|
| 创作者（定内容/选片） | 全程 | 全程 | 闸门处 | 闸门处 |
| 工程（写脚本/运维） | 不需要 | 半天 | 2–3 天 | 1 周 |
| 导演（分镜/调度） | 全程 | 全程 | 全程 | 立项与验收 |

**一个人做**：建议停在 L2。L3 的自恢复需要有人处理异常，一个人值夜不现实。
**两个人**：L3 可行，但要先约定「谁按暂停、谁看报警」。

---

## 8. 升级与降级判据

### 升级

| 信号 | 升到 |
|---|---|
| 每镜超过 10 分钟在重复操作 | L1 |
| 同一类错误重复 2 次以上 | L2 |
| 一集内需要跑超过 20 镜，且要夜间跑 | L3 |
| 要做第二、第三集 | 至少 L2 |

### 降级

| 信号 | 降回 |
|---|---|
| 设计每周都在变 | L0/L1（自动化会锁死你） |
| 判据还没定义清楚 | L1 |
| 检查器误报超过真实问题 | 先修阈值，而不是继续加规则 |
| 没人看审计日志 | L1（自动化已经名存实亡） |

## 9. 最后一条

> **档位是给流程用的，不是给面子用的。**
>
> 停在 L2 的一集完整作品，比卡在 L3 半年的「全自动系统」有价值。

选一档，写进项目 README，然后按那一档的验收标准做。
