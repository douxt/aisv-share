# 适配器契约：换栈只换六个函数

> 这一篇是整个分享包的技术核心。
> 它把「方法层」和「你选的工具」接起来：方法层给判据，契约给接口，你的实现只要填进去。
>
> 它**不绑定**任何模型、语言或框架。示例用 Python 写，但语义与语言无关。

---

## 1. 为什么需要契约

没有契约时，换一个模型意味着：

- 重写提示词格式
- 重写截帧脚本
- 重写拼接脚本
- 重写检查逻辑
- 重新对一遍所有判据

有契约后，换模型只需要：

> **实现六个函数，声明它的能力。**

其余东西——流程、门禁、失败处理、拼接逻辑、验收清单——全部复用。

**判断你的实现是否合格，只有一条**：拿这六个函数能跑通 `05-验收清单.md`。

---

## 2. 方法判据 → 函数映射

先把「方法层说的话」翻译成「需要什么函数」。这张表是契约存在的理由。

| 方法层的判据 | 需要的函数 | 说明 |
|---|---|---|
| 生成一个镜头 | `generate` | 唯一与模型强绑定的函数 |
| 首帧锁定（锁帧三件套之二） | `extract_tail` + `generate(ref_images[0])` | 导出尾帧图 |
| 运动延续（三件套之三） | `extract_tail` + `generate(ref_video)` | 导出尾段视频 |
| 首帧像素差 < 25 及格 | `compare_frames` | 生成首帧 vs 尾帧图 |
| 产物分辨率 == 规格 | `measure` | 实测，不信任文件名 |
| 音频峰值 ≤ 0dB | `measure` | 真峰值，不是 RMS |
| 拼接总时长 = 逐镜实测累加 | `measure` + `join_clips` | 禁用乘法 |
| 接缝交叉淡化 | `join_clips` | xfade + 音频交叉 |
| 交付分辨率放大 | `upscale` | 可选能力 |
| 「同一类失败连续 3 次 = 系统性」 | 编排层 | 不属于契约，属于流程 |

**反向检查**：如果某条判据在这张表里找不到对应函数，说明这条判据还没落地——要么补函数，要么承认它是人工判断。

---

## 3. 配置：spec

一个文件，唯一事实源。下面用 YAML 写是为了能加注释；实现用 JSON 也完全可以，字段一致即可（可跑的 JSON 版本见 `templates/spec.json`）。

```yaml
revision: "1"

stack:                          # 由 00-能力清单.md 填出来
  name: "your-model"
  version: "2026-xx"
  capabilities:
    max_shot_sec: 15
    max_ref_images: 5
    supports_first_frame: true
    supports_ref_video: true
    ref_video_frames: 24
    supports_audio_ref: true
    max_audio_refs: 3
    output_has_audio: true
    reproducible_seed: true
    scriptable: true
    predictable_duration: false   # 时长不恒定 → 必须逐镜实测

generate:
  draw:                         # 抽卡档
    resolution: [704, 384]      # 宽, 高
    steps: 4
    sampler: ""
    seed_range: [10000, 19999]
  refine:                       # 精修档
    resolution: [1280, 704]
    steps: 8
    seed_range: [20000, 29999]

relay:
  tail_frames: 24               # 运动延续帧数
  reencode: true                # 必须重编码，禁止流拷贝

seam:
  xfade_sec: 0.2
  audio_xfade_sec: 0.2

deliver:
  width: 1920
  height: 1080
  fps: 24
  lufs: -16
  audio_sample_rate: 48000

thresholds:
  first_frame_diff_good: 15
  first_frame_diff_ok: 25
  first_frame_diff_fail: 50
  audio_peak_max_db: 0.0

paths:
  project_root: "."
  work_dir: "./work"
  output_dir: "./output"
  assets_dir: "./assets"
```

**规则**（与我们踩过的坑一一对应）：

1. 所有数字只出现在这里，脚本里禁止硬编码；
2. 跑前做**等值校验**：模板/请求的参数必须 == spec，不是「不小于」；
3. 跑后做**产物校验**：实测分辨率/时长/帧数必须 == spec，不信任文件名；
4. `capabilities` 参与校验：如果 spec 里某个镜头需要 15 秒但 `max_shot_sec: 10`，**在跑之前就中止**。

## 4. 六个函数

### 4.1 `generate`

```python
def generate(request: GenerateRequest) -> GenerateResult:
    """
    输入：
      request.prompt            str        完整提示词（结构由你的栈决定）
      request.ref_images        [path]     参考图，顺序有意义：
                                            [0] 若是衔接镜 = 上一镜尾帧
      request.ref_video         path|None  运动延续用尾段视频
      request.audio_refs        [path]     音色参考
      request.seed              int
      request.duration_sec      float
      request.resolution        (w, h)
      request.steps             int
      request.mode              "draw" | "refine"

    输出：
      result.video_path         path
      result.seed_used          int       必须回传实际使用的种子
      result.width, height      int       实测
      result.fps                float     实测
      result.duration_sec       float     实测，不要写请求值
      result.has_audio          bool
      result.elapsed_sec        float
    """
```

**必须保证**：

- 产物文件存在且能被探针工具读出规格；
- 返回的 `duration_sec` 是**实测值**，不是你把请求值抄回来；
- `seed_used` 真实记录了本次使用的种子（否则无法复现、无法归档）；
- 失败时抛出明确异常，**不要返回一个空文件或旧文件**。

**常见错误**：

| 错误 | 后果 |
|---|---|
| 返回请求的时长而不是实测 | 拼接时长全错 |
| 复用旧产物（缓存/key 撞名） | 你以为在看新版，其实是旧版 |
| 失败时静默返回上次的产物 | 最危险：全流程「成功」，片子是错的 |
| 不记录种子 | 无法复现、无法做对照 |

### 4.2 `extract_tail`

```python
def extract_tail(video: path, frames: int) -> TailResult:
    """
    输入：完整镜头的成片、要截取的帧数
    输出：
      result.image_path    path   尾帧（PNG）
      result.video_path    path   尾段（frames 帧）
      result.start_sec     float  尾段起点
      result.frame_count   int    实测帧数
    """
```

**必须保证**：

- `video_path` 是**重新编码**过的，不是流拷贝；
- `frame_count` 精确等于 `frames`（实测，不是估算）；
- 两者来自同一段画面：图片 = 尾段最后一帧；
- 如果源视频尾段是坏帧（花屏/黑帧/变形），提供截断参数，允许从更早的位置取。

**为什么必须重编码**：流拷贝会保留原片的关键帧结构，截出来的开头常是延迟/损坏帧。我们量过一次：重编码后首帧位移从 24 像素降到 6–14 像素。

### 4.3 `measure`

```python
def measure(video: path) -> MediaInfo:
    """
    输出：
      width, height        int
      fps                  float
      duration_sec         float
      frame_count          int
      has_audio            bool
      audio_sample_rate    int
      audio_peak_db        float     真峰值；无音轨则 None
    """
```

**必须保证**：全部是实测值。这个函数是**所有门禁的地基**——它错，上面全错。

**不要**用 `duration = frame_count / fps` 反推，除非你确认容器元数据不可靠；两者都要取，不一致时以解码实测为准。

### 4.4 `compare_frames`

```python
def compare_frames(a: path, b: path, resize_to: (w, h) = None) -> float:
    """
    输出：平均绝对像素差（0 = 完全相同；范围 0–255）
    两图分辨率不同时，先缩放到同一尺寸再比。
    """
```

**必须保证**：

- 两图尺寸不同时先统一尺寸，否则比较无意义；
- 返回 0–255 的标准化度量，阈值才有可比性；
- 同一张图自比必须为 0（契约自测会验）。

**注意**：像素差小 ≠ 衔接正确。人物数量、朝向、动作都可能与图不一致。这个指标是**必要的机械底线**，不是充分条件。

### 4.5 `join_clips`

```python
def join_clips(clips: [path], xfade_sec: float, audio_xfade_sec: float) -> JoinResult:
    """
    输出：
      result.video_path
      result.durations     [float]   每个输入的实测时长
      result.total_sec     float
      result.offsets       [float]   每个接缝的实际 offset
    """
```

**必须保证**：

- 逐镜**实测**时长后累加：`acc += d_i - xfade`，`offset_i = acc - xfade`；
- 禁止用「镜数 × 单镜时长」；
- 音视频同步；音频也做交叉淡化；
- 输入规格不一致时**直接报错**，不要静默缩放。

**真实事故**：公式写成 `i × d - xfade`，25 镜成片被截短 27 秒，直到审片才发现。

### 4.6 `upscale`（可选）

```python
def upscale(video: path, factor: float, target: (w, h)) -> path:
    """
    输出：放大后的视频
    """
```

**必须保证**：

- 在**单镜层**执行，不在拼接后的整片执行（内存与质量都更差）；
- 分批处理，每批后释放缓存（整段一次载入会 OOM）；
- 不改变时长、帧率、音轨。

**没有这个能力也能交付**：直接用 `join_clips` 前的原始分辨率，或换一个纯 ffmpeg 缩放。质量会低一些，但流程不断。

## 5. 产物 sidecar：可追溯

每个产物旁边放一个同名 `.json`：

```json
{
  "spec_revision": "1",
  "stack": {"name": "your-model", "version": "2026-xx"},
  "shot": "act4_4a",
  "mode": "refine",
  "seed": 20013,
  "prompt_sha256": "...",
  "refs": ["tail.png", "hero.png"],
  "ref_sha256": ["...", "..."],
  "requested": {"duration_sec": 10.0, "resolution": [1280, 704]},
  "actual": {"duration_sec": 10.125, "width": 1280, "height": 704, "fps": 24},
  "elapsed_sec": 742.3,
  "created_at": "2026-01-01T00:00:00"
}
```

**为什么**：三个月后你会问「这条片子是用哪版提示词、哪个种子、哪套配置生成的」。没有 sidecar，只能靠猜。

**门禁用法**：产物 sidecar 里的 `spec_revision` 与当前 spec 不一致 → 判定为旧图产物，不得进入验收。

## 6. 契约自测：六条断言

写完之后，先跑这六条。**全过才算可用。**

| # | 断言 | 目的 |
|---|---|---|
| 1 | `generate` 返回的文件存在，`measure` 分辨率 == 请求值（±2px） | 证明产物真实且规格正确 |
| 2 | `generate` 返回的 `duration_sec` 与 `measure` 的实测值相差 < 0.05s | 证明没有把请求值抄回来 |
| 3 | `extract_tail(video, 24)` 的 `frame_count` == 24 | 证明帧数精确 |
| 4 | `compare_frames(a, a) == 0`，且 `compare_frames(a, b) > 0` | 证明度量有区分度（否则门禁形同虚设） |
| 5 | 拼接两段 10s：`total_sec ≈ 20 - xfade`（±0.15s） | 证明累加公式正确 |
| 6 | `upscale` 前后 `duration_sec` 与 `fps` 不变（±0.05s） | 证明没有偷偷改时间轴 |

**第 4 条尤其重要**：如果 `compare_frames` 对任何两张图都返回 0 或都返回同一个数，门禁就是装饰品。我们踩过——检查器「通过」，片子是坏的。

**回归要求**：准备一组已知好/坏的样本，每次改适配器后重跑，确认「好片必过、坏片必拦」。

## 7. 最小实现量

| 函数 | 参考实现量 | 说明 |
|---|---|---|
| `generate` | 50–150 行 | 主要是把 spec 映射到你的工具的请求格式 + 轮询 |
| `extract_tail` | 20–40 行 | 一次重编码 + 一次取帧 |
| `measure` | 20–40 行 | 调探针工具 |
| `compare_frames` | 10–20 行 | 缩放到同尺寸 + 求差 |
| `join_clips` | 40–80 行 | 累加 offset + 交叉淡化 |
| `upscale` | 20–60 行 | 可选 |

**合计 160–390 行**。这就是「换栈」的全部工作量。

其余东西（流程编排、门禁判定、失败归类、文档）不需要重写。

## 8. 不写代码的版本（L0）

如果你暂时不做脚本，六个函数对应成六种手工操作，语义完全一样：

| 函数 | 手工对应 |
|---|---|
| `generate` | 在界面里填参数提交，记下种子 |
| `extract_tail` | 用剪辑软件取最后 1 秒导出图片 + 视频 |
| `measure` | 右键属性 / 播放器信息 / 探针工具 |
| `compare_frames` | 并排看（**注意：人眼对 15–25 像素差不可靠**，建议还是脚本） |
| `join_clips` | 剪辑软件接，注意交叉淡化 |
| `upscale` | 放大工具 |

**代价**：手工档无法做批量与一致性校验，容易漏项。适合验证可行性，不适合量产。

## 9. 五个反模式

| 反模式 | 为什么错 |
|---|---|
| **把模型调用写进流程代码** | 换模型时整条流程要改。必须隔在 `generate` 后面 |
| **用文件名推断规格** | 文件名会骗人。一律实测 |
| **门禁阈值写进检查器** | 换栈后阈值要重标定。阈值放 spec，检查器只读 |
| **产物没有 sidecar** | 三个月后无法回答「这是哪一版」 |
| **失败时返回上一次的产物** | 全流程显示成功，交付的是旧片——最难查的一类事故 |

## 10. 契约的验收标准

> **能把 `05-验收清单.md` 从第一条跑到最后一条，且每条都能给出命令和期望值。**

不是「读懂了」，不是「大概能接上」。
