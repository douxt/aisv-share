# 第一镜走查：从零到一条 5 秒片

> 落地层第 3 篇。照着做，大约 1–2 小时（含环境与首次生成）。
> 目标不是做得好，是**把整条链跑通，并且知道每一步该看到什么**。

---

## 0. 这条走查要证明什么

一个「冒烟镜」（smoke shot）。它必须覆盖：

| 要素 | 数量 | 为什么 |
|---|---|---|
| 角色 | 1 个 | 排除多人串扰变量 |
| 场景 | 1 个 | 排除背景混乱 |
| 运镜 | 1 个 | 排除运镜冲突 |
| 事件 | 1 个 | 排除节奏问题 |
| 时长 | 5 秒 | 最短的可用单位 |
| 衔接 | 先不接 | 衔接单独一步做 |

**不要**在第一镜上做：10 秒、双人、特效、唱歌、打斗。任何一个都会让你分不清是「链路没通」还是「内容不对」。

## 1. 准备

### 1.1 目录

```
<project>/
├── spec.json              # 配置（见 02-适配器契约 §3）
├── adapter.py             # 你的六个函数
├── assets/
│   └── hero.png           # 一张角色图
├── shots/
│   └── smoke_01.md        # 提示词
└── out/
```

### 1.2 填 spec

从 `templates/spec.json` 复制，改三处：

1. `stack.capabilities` —— 用 `00-能力清单.md` 的实测结果填；
2. `generate.draw.resolution` —— 先用你**跑得动**的最低档（不要一上来 1080p）；
3. `paths` —— 指向你的目录。

**自洽检查**：`capabilities.max_shot_sec` 必须 ≥ 你打算生成的秒数。不等就先改，不要硬跑。

### 1.3 确认适配器的六个函数能导入

```bash
python -c "import adapter; print([n for n in ('generate','extract_tail','measure','compare_frames','join_clips') if not hasattr(adapter,n)])"
```

**期望**：输出 `[]`。

**如果报错**：先修导入问题，不要开始写提示词。

## 2. 写第一份提示词

复制 `templates/skill/samples/good.md` 改。

最小结构（六段职能）：

```
subject_definitions:  一个主体，绑定 <Picture 1>
summary:              一句话：镜头做什么
retention_analysis:   一行：参考图保留什么
detailed_description: 风格句 + 3–4 个时间戳 + 落定 + 质感约束
overall_soundscape:   一句环境声
non_diegetic_music:   一句配乐
```

示例（5 秒、一个角色、缓慢推近）：

```text
subject_definitions:
<Subject 1> is the girl in <Picture 1>: white hair, dark robe, standing at stage center.

summary:
[reference generation] A slow push-in on the girl as she raises one hand.

retention_analysis:
<Subject 1>: fully_preserved - hair, robe, and posture are retained.

detailed_description:
A calm stage scene with cool violet key light, teal shadows, shallow depth of field.
At 00:00.000 the shot opens on <Subject 1> at stage center, facing the camera.
At 00:01.500 she raises her right hand to chest height, fingers open.
At 00:03.500 the camera pushes in slowly toward her face.
At 00:04.500 she holds the pose, the frame settles.
No stiff motion, no frozen limbs.

overall_soundscape:
Soft room tone with a faint hum of stage lights.

non_diegetic_music:
A sparse piano cue, one note, fading under the hold.
```

### 校验（必跑）

```bash
python <skill>/scripts/validate.py shots/smoke_01.md --duration 5
```

**期望**：`ERROR 0`。出现 WARN 时逐条判断，把理由记下来。

**常见拦下原因**：

| 输出 | 改法 |
|---|---|
| `L1.timestamp 最后时间戳超过时长` | 把最后时间戳压到 ≤5s |
| `L2.negative 否定指令` | 改成正面状态 |
| `L1.labels 引用了未定义参考图` | 在 subject_definitions 里补定义 |
| `L3.budget 参考图超上限` | 减少参考图 |

## 3. 生成（1 发）

```bash
python -c "
import adapter, json
req = {'prompt': open('shots/smoke_01.md',encoding='utf-8').read(),
       'ref_images': ['assets/hero.png'], 'ref_video': None, 'audio_refs': [],
       'seed': 10001, 'duration_sec': 5.0, 'resolution': [704,384],
       'steps': 4, 'mode': 'draw'}
r = adapter.generate(req)
print(json.dumps(r, default=str, indent=2))
"
```

**期望**：

- 返回里有 `video_path`；
- `duration_sec` 与 5.0 接近；
- `elapsed_sec` 与你的能力清单里记录的量级一致（差太多 = 实际跑的不是你以为的档位）。

**如果卡住超过能力清单里记录时长的 2 倍**：不要继续等。按 `00-能力清单.md` Q8 的方法查进度；没有进度可查时，检查 GPU/磁盘活动。

## 4. 验收这一条

```bash
python -c "import json,adapter; print(json.dumps(adapter.measure('out/smoke_01.mp4'), default=str))"
ffmpeg -nostats -i out/smoke_01.mp4 -af astats=metadata=1:reset=0 -f null - 2>&1 | grep -i "Peak level"
```

对照 `05-验收清单.md` 的 A1 / A2 / B3：

| 项 | 期望 |
|---|---|
| 分辨率 | == 请求（±2px） |
| 时长 | 与 5.0 差 < 0.05s |
| 音轨 | 存在（若能力声明支持） |
| 峰值 | ≤ 0 dB |

**看片**：完整看两遍。第一遍看内容（有没有做到）；第二遍看瑕疵（手、脸、背景、闪烁）。

## 5. 跑第二发：学会对照

同提示词、**换种子**，再跑一次。

```bash
# seed 改成 10002，其余不变
```

### 为什么要做这一步

单发不能判断提示词好坏——一次生成里很大一部分是随机性。第二发给你两个信息：

1. 哪些问题是**稳定的**（两发都错 → 提示词/设计问题）；
2. 哪些是**随机的**（一发错一发对 → 重抽即可）。

**判据**：如果两发错在同一处，先改提示词，不要继续抽。

## 6. 做一次衔接

现在拿第一镜的尾帧，做第二镜。

### 6.1 截尾

```bash
python -c "import adapter,json; print(json.dumps(adapter.extract_tail('out/smoke_01.mp4', 24), default=str))"
```

**期望**：`frame_count == 24`；得到一张尾帧图 + 一段尾段视频。

### 6.2 写第二镜提示词

与第一镜相同，另加三条：

1. `subject_definitions` 第一句改为：`<Subject 1> is the opening frame in <Picture 1>, the final frame of the previous shot: <逐项复述：姿态、手在哪、表情、背景状态>`
2. 参考图列表：尾帧图排**第一位**；
3. `summary` 写明开场锁定上一镜尾帧。

### 6.3 生成（带运动延续）

请求里加：

```python
'ref_images': ['out/smoke_01_tail.png', 'assets/hero.png'],
'ref_video':  'out/smoke_01_tail24.mp4',
```

### 6.4 验收衔接

```bash
# 取第二镜第一帧，与第一镜尾帧比较
python -c "import adapter; print(adapter.compare_frames('<smoke_02_first>.png','out/smoke_01_tail.png'))"
```

| 值 | 结论 |
|---|---|
| < 15 | 优 |
| 15–25 | 及格，可继续 |
| 25–50 | 检查描述漏项 / 换种子重抽 |
| ≥ 50 | 先怀疑设计矛盾（是不是这一镜本来就该硬切） |

## 7. 拼接

```bash
python -c "import adapter,json; r=adapter.join_clips(['out/smoke_01.mp4','out/smoke_02.mp4'],0.2,0.2); print(json.dumps(r,default=str,indent=2))"
```

**期望**：`total_sec ≈ dur1 + dur2 - 0.2`。

看接缝：是否卡顿、色调是否跳、人物位置是否连续。

---

## 8. 常见卡点

| 现象 | 先查什么 | 不要做什么 |
|---|---|---|
| 产物 0 字节 | 权限 / 输出目录 / 磁盘空间 | 不要重复提交 |
| 分辨率不对 | 内部对齐到 32 的倍数？ | 不要在手写脚本里补缩放 |
| 时长差很大 | spec 与请求是否一致；模型是否支持该时长 | 不要用乘法估算总时长 |
| 每次结果都不同 | 种子是否生效；是否可复现 | 不要做严格的 A/B |
| 音频峰值 > 0dB | 直接换一发 | 不要试图修音 |
| 首帧怎么都对不上 | 尾帧图是否在首位；描述是否按图写 | 不要继续抽卡 |
| 接缝卡顿 | 尾段视频帧数 / 是否重编码 | 不要靠加淡化掩盖 |
| 生成很慢 | 是否跑在高分辨率档 | 不要同时跑别的 GPU 任务 |

## 9. 走完之后

### 9.1 你验证了什么

- 生成、测量、截取、比较、拼接五个函数都能用；
- 提示词能过校验；
- 一条完整的「生成 → 验收 → 衔接 → 拼接」链路成立；
- 你知道单镜的真实耗时（可以用它排期了）。

### 9.2 还不能证明什么

- 质量好不好（那是审美判断，需要多看几镜）；
- 能不能上量（批处理、断点续跑、资源管理还没测）；
- 多人镜、特效、长镜是否可靠。
