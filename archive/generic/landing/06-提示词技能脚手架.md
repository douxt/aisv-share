# 提示词技能脚手架：把提示词规范交给 agent 执行

> 落地层第 6 篇。
> 我们生产时不是「靠自己记得怎么写」，而是调用一个 **skill**：一套可执行规约 + 权威规则源 + 强制自检。
> 这一篇讲怎么把你自己的规范做成同样的东西。

---

## 1. skill 是什么

不是「提示词库」，不是「写作技巧文档」。

它是一份**给 agent 的操作规程**，必须包含四件事：

| 段 | 作用 | 没有会怎样 |
|---|---|---|
| **1 输入识别** | 判断这次是什么任务（文生视频 / 图生视频 / 首尾帧 / 多参考） | agent 用错格式 |
| **2 权威规则源** | 指定必须读哪个文件，禁止凭记忆 | agent 编造字段名、段序 |
| **3 强制自检** | 可执行脚本，ERROR 必须改 | 规则写在纸上，没人执行 |
| **4 交付报告** | 命中了哪些规则、校验结果如何 | 人无法快速复核 |

**核心**：规则写在文件里，每次执行都读。模型记不住「六段式顺序」这种东西，也不该记。

---

## 2. 文件布局

```
<your-skill>/
├── SKILL.md                 # 规程：做什么、按什么顺序、什么时候停
├── references/
│   ├── format-<mode>.md     # 权威格式源（每个模式一份）
│   ├── rules-domain.md      # 领域规则（如打斗/舞蹈/产品）
│   └── examples.md          # 正例/反例成对
├── scripts/
│   └── validate_prompt.py   # 机械检查：结构、反模式、预算
└── templates/
    └── prompt.md            # 可直接复制的骨架
```

**原则**：`SKILL.md` 只写「流程与判据」；所有**内容规范**放 `references/`。这样规则可单独更新，不用动流程。

---

## 3. SKILL.md 模板（可抄）

```markdown
---
name: <your-prompt-skill>
description: <一句话：什么时候该用这个技能>
---

# 提示词生成规程

## 输入识别
1. 判断模式：<列出你的模式，例如 文生/图生/首尾帧/多参考>
2. 读取对应 `references/format-<mode>.md`，**严格按其中的段名、段序、标签格式**。

## 生成规则
1. 只写可执行指令：谁、在哪、做什么、镜头怎么动、什么声音。
2. 时间轴：每个事件给时间戳；最后一点接近镜头结尾；结尾必须有落定状态。
3. 参考图：每张图一个职责；衔接镜的首帧图排第一，并逐项复述其内容。
4. 禁止：负面指令、步数、空泛形容词（见 `references/examples.md` 反例）。

## 必跑校验（不得跳过）
- `python scripts/validate_prompt.py <prompt> --duration <sec>`
- `python <your-project>/check_scene_chain.py <shot>`（若项目有）
- 所有 `[ERROR]` 必须清零；`[WARN]` 逐条判断并说明保留理由。

## 交付报告
向人汇报时必须包含：
1. 命中的规则清单（用了哪几条）；
2. 改写掉的反例（原文 → 改后）；
3. 校验输出原文（ERROR/WARN 计数）。
```

## 4. references 怎么写

| 要 | 不要 |
|---|---|
| 正例/反例成对出现 | 只写「要具体、要生动」这类原则 |
| 按类别分节（构图/动作/声音/台词） | 按时间顺序堆案例 |
| 每条规则说明「为什么」 | 只给结论 |
| 明确的禁用词表 + 替代写法 | 「尽量少用」 |

**最有用的一节是反例**。写作规范容易被记住，反例才是「我到底错在哪」的定位器。

**规则源必须是唯一权威**：如果两处都写了同一条规则，它们迟早会漂移。领域规则（比如技能表、武器禁词）单独成文件，别处只引用。

---

## 5. validator 怎么写

### 输出格式

```
[ERROR] L1 timestamps: 最后时间戳 11.2s 超过镜头时长 10.0s（第 34 行）
[WARN]  L2 negative: "does not turn" 可能反向激活，建议改成正面状态（第 21 行）
```

要求：
- 每行带层级、类别、具体位置；
- ERROR 与 WARN 分开计数；
- 退出码：0 = 无 ERROR；1 = 有 ERROR；2 = 工具本身不可用。

### 检查项顺序

先便宜后贵：文件存在 → 结构 → 反模式词 → 预算 → 跨文档。

### 必须写的两类检查

1. **结构**：段齐、序对、标签闭合、时间戳单调且不超时长；
2. **反模式**：负面词、数字步数、空泛词、禁词、参考图超限、锁帧图不在首位。

### 回归样本

准备「3 份好稿 + 每类毛病 1 份坏稿」。改规则就重跑，确认好稿不被误拦、坏稿被拦在正确位置。

## 6. agent 使用协议

给读者的 agent 用的最小约定：

| 项 | 约定 |
|---|---|
| **何时调用** | 每写完一镜提示词，必须调用；不允许「先跑一版看看」 |
| **不允许** | 跳过 validator；不允许自己发明段名/标签；不允许在 validator 报错时改为「手动判断通过」 |
| **停机条件** | ERROR > 0 → 不生成；同一原因连续 3 次 → 停下报告，不许继续改措辞 |
| **交付物** | 提示词 + 校验输出 + 改动说明（原文→改后），三者一起交 |
| **人闸** | 校验通过后仍必须由人确认设计意图（G2），不自动进入生成 |

**为什么写停机条件**：没有停机的 agent 会用「再试一次」把错误放大成几小时 GPU 时间。

---

## 7. 五个反模式

| 反模式 | 后果 |
|---|---|
| skill 变成提示词库 | agent 只会抄样式，不会按流程执行 |
| 规则只写原则不写反例 | 出了问题无法定位 |
| validator 只查格式 | 结构全绿，内容是废的 |
| 没有回归样本 | 规则一改就静默失效 |
| 校验通过就自动生成 | 机器判据替代了人的设计判断 |

---

## 8. 可运行的骨架

`templates/skill/` 是一份可直接复制、改完就能跑的模板：

- `SKILL.md`（规程）、`references/format.md`（格式源）、`references/examples.md`（正/反例）；
- `scripts/validate.py`：零依赖检查器，9 条规则，ERROR/WARN 分级，带 `--selftest`；
- `samples/`：1 份好样本 + 5 份各错一种的坏样本。

用法：复制目录 → 改 `REQUIRED_SECTIONS` 与正则 → `python scripts/validate.py --selftest` 必须 6/6。

自测只证明「这几条规则有牙」，不证明覆盖到位——新规则必须配新坏样本。

## 9. 我们这版长什么样

见 `03-stack/提示词技能.md`。要点：

- 规程 7 步：识别模式 → 读权威格式 → 生成 → 领域规则复核 → 跑校验器 → 跑场景链检查 → 交报告；
- 权威格式源是文本文件，不是记忆；
- 领域规则有独立文件（战斗技能表、空间规则），别处只引用；
- 两个强制脚本（结构校验 + 场景链）+ 两个半自动检查（锁帧语义、空间断言）。

**迁移提示**：规程的四段骨架可以直接搬；段名、标签、脚本内容必须按你的栈重写。
