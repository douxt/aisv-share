# 提示词生成规程（模板）

> 把 `<...>` 换成你的内容。删除不适用的段落，但四段骨架不要删。

## 1. 输入识别

1. 判断模式：`<模式 A>` / `<模式 B>` / `<模式 C>`。
2. 读取对应格式源：`references/format.md`（**禁止凭记忆**写段名、标签、字段顺序）。
3. 读取领域规则：`references/examples.md`（正例/反例成对）。

## 2. 生成规则

1. 只写可执行指令：谁、在哪、做什么、镜头怎么动、什么声音。
2. 时间轴：每个事件给时间戳；最后一点接近镜头结尾；结尾必须有落定状态。
3. 参考图：每张图一个职责；衔接镜的首帧图排第一，并逐项复述其内容。
4. 禁止：负面指令、步数、空泛形容词（见 `references/examples.md`）。
5. 规则冲突时，以 `references/format.md` 为准。

## 3. 必跑校验（不得跳过）

```bash
python scripts/validate.py <prompt.md> --duration <镜头秒数>
```

- 所有 `[ERROR]` 必须清零；
- `[WARN]` 逐条判断，并在交付报告里说明为什么保留；
- 有项目级检查器（如场景链）时一并运行。

**不允许**：validator 报错后改为「人工判断通过」。

## 4. 交付报告

向人汇报时必须包含：

1. 命中的规则清单；
2. 改写掉的反例（原文 → 改后）；
3. 校验输出原文（ERROR/WARN 计数）。

> 校验通过不等于可以生成。设计意图仍需人确认（G2）。

## 5. 停机条件

- ERROR > 0 → 不生成；
- 同一原因连续 3 次被拦 → 停止改措辞，报告设计问题；
- 无法判断 WARN 是否可忽略 → 交给人，不要自行放行。
