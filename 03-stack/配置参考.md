# 配置参考：`code/twopass_spec.json`

> 唯一事实源。所有脚本从这里读；跑批前 preflight 做**等值**校验；产物再做一次实测校验。
> 改配置 = 改这个文件 + 提交 + 人审。禁止在命令行临时覆盖。

---

## 1. 字段表

### env（换机器只改这里）

| 字段 | 示例 | 说明 |
|---|---|---|
| `h3_root` | `C:/AI/ComfyUI_H3` | 视频实例根目录（示例路径，可改） |
| `h3_port` | `8188` | API 端口（`run_twopass_auto.py` 的 URL 由它生成） |
| `project_root` | `.`（当前目录） | 项目根；也可用 `AISV_PROJECT_ROOT` 覆盖 |

### 生成主链

| 字段 | 值 | 管什么 | 错了会怎样 |
|---|---|---|---|
| `chain` | `legacy` | 采样链型 | 变成已删包的旧链 → 提交 400 |
| `pass1_mp` | `0.26` | 抽卡像素预算 | 实际产出 704×384 |
| `pass1_resolution` | `704x384` | 抽卡分辨率（派生） | 与模板不符 → preflight 中止 |
| `upscale_scale` | `1.8333` | 二采放大倍数 | 704×384 × 1.8333 → 1280×704 |
| `deliver_resolution` | `1280x704` | 单镜交付分辨率 | 超分脚本必须派生此值 |
| `label` | `384p10` | 模板命名标签 | 与文件名/产物命名绑定 |

### 采样

| 字段 | 值 | 说明 |
|---|---|---|
| `sampler` / `scheduler` | `euler` / `simple` | 稳定组合 |
| `shift_video` | `12.0` | 视频 sigma shift |
| `audio_shift` | `6.0` | 音频 sigma shift |
| `pass2_sigmas` | `0.9035,0.8000,0.6316,0.3158,0.0000` | 二采 5 级 sigma |
| `seed_policy` | 递增不复用 | 改稿必换域 |

### 衔接

| 字段 | 值 | 说明 |
|---|---|---|
| `video_ref_policy` | 锁帧镜必须带尾段参考 | 一句话策略 |
| `video_ref_frames` | `24` | 尾段帧数（精确值，不是下限） |
| `relay_tail_sec` | `0.05` | 截取尾部容差 |
| `relay_fps` | `24` | 参考视频帧率 |
| `seam_policy` | 交叉淡化 + 可选颜色匹配 | 后处理 |
| `seam_xfade_sec` | `0.2` | 视频交叉时长 |
| `seam_audio_crossfade_sec` | `0.2` | 音频交叉时长 |
| `seam_audio_sample_rate` | `48000` | 统一采样率 |

### 审片与超分

| 字段 | 值 | 说明 |
|---|---|---|
| `preview_times` | `1.5,4.0,6.5,9.0` | 抽帧时间点 |
| `upscale_policy` | 单镜逐帧 2× | 禁整段 |
| `upscale_model` | 2× 保守模型 | 路径 |
| `upscale_batch` | `2` | 批大小（16 = OOM 事故）；由 `upscale_batch.py` 传给 `upscale_frames.py` |
| `upscale_target` | `1920x1080` | 交付分辨率 |

### 禁用节点

`forbidden_nodes` 列出已删包/不稳定的节点。preflight 会检查模板中不得出现。
**这一节是事故记录**：每次删包或淘汰方案，把节点名加进来，防止旧模板复跑。

## 2. 三条校验

| 时机 | 校验 | 不通过 |
|---|---|---|
| 跑前 | 模板链型/分辨率 == spec | 中止 |
| 跑前 | 参考视频帧数 == `video_ref_frames`（等值） | 中止 |
| 跑后 | 产物实测分辨率 == `deliver_resolution` | 判为失败 |

**为什么是等值而不是下限**：H3 硬下限是 5 帧，但执行标准是 24 帧。用「≥5」会让 7 帧的残缺参考混过去。

---

## 3. 事故史（每个字段为什么存在）

| 事故 | 对应机制 |
|---|---|
| 模板链型从 legacy 漂到已删包的旧链 → 提交 400 | `chain` + `forbidden_nodes` + preflight |
| 抽卡像素预算 0.41 被脚本默认值 0.26 覆盖 | 默认值全部从 spec 读，脚本内禁止硬编码 |
| 尾段帧数写成 5–8 帧（当成下限） | 等值校验 == 24 |
| 超分输出 1280×712（写死变体） | 从 `deliver_resolution` 派生 |
| 审片时间点两套（手动 vs 脚本） | `preview_times` |
| 拼接交叉时长各处不同 | `seam_xfade_sec` |
| upscale 批大小 16 → 内存爆 | `upscale_batch: 2` 且写进默认值（不是注释） |
| 拼接用乘法估时长 → 少 27 秒 | 逐镜实测累加，与 spec 无关，但同属「配置即契约」 |

## 4. 改配置的正确姿势

1. 改 `code/twopass_spec.json`；
2. 在 `history` 数组追加一条：日期 + 改了什么 + 为什么（事故或实测依据）；
3. 跑一次单镜全链，确认产物规格；
4. 提交 + 推送。

**反面教材**：在命令行传 `--pass1-mp 0.41` 覆盖默认值。这次跑对了，下次忘了就漂了——这正是当初七起事故的共同形态。

---

## 5. 与本包的差异

这份 spec 包含具体模型名、路径与数值，属于「2026-09 的本机事实」。
换机器/换版本时，`env` 段必改；生成数值建议用 `04-上手/01-验收清单.md` 重新标定后再改。
