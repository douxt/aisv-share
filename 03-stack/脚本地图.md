# 参考实现：脚本地图与执行入口

> **时效声明**：本节绑定我们 2026 年 9 月使用的具体技术与版本。它大概率会过时。
> 读它的时候请关注**结构**（配置源、入口、门禁、构建链），而不是具体命令。
>
> **脚本位置**：随包代码在 `code/`；下文写的 `diag/xxx.py` 对应 `code/xxx.py`。

---

## 1. 技术栈组成

| 角色 | 类型 | 说明 |
|---|---|---|
| 视频生成 | 图生视频/多参考视频模型 | 18GB 级，消费级 16GB 显卡可跑（降分辨率档） |
| 参考视频 | 同一模型支持「上一镜尾段」作为参考 | 需要模型支持视频参考输入 |
| 文生图 | 角色/场景资产 | 需支持多视角一致性 |
| 视觉语言模型 | 审图/语义检查 | 本地小模型即可（~4B） |
| 超分 | 图像放大模型 | 2 倍，逐帧批处理 |
| 编排 | Python 脚本 + 本地服务 HTTP API | 无框架依赖 |
| 存储 | JSON 配置 + Markdown 源文档 | 全部纯文本可版本化 |

**设计取舍**：不引入工作流编排框架，用「脚本 + 配置文件」保持每一步可单独调试、可单独替换。

---

## 2. 架构：配置唯一事实源

```
spec.json                        ← 唯一的参数来源
  ├─ env 段：根路径 / 端口        ← 换机器只改这里
  ├─ 生成规格：分辨率 / 步数 / 采样 / LoRA
  ├─ 衔接规格：尾帧帧数 / 交叉淡化时长
  ├─ 执行入口注释                ← 哪个操作必须走哪个脚本
  └─ 历史记录                    ← 每次改配置的原因
        │
        ▼  所有脚本从这里读，禁止命令行手敲参数
  构建模板 → 跑批 → 门禁 → 接力 → 拼接 → 超分
```

**规则**：
1. 改配置 = 改 spec 文件 + 提交，不通过命令行覆盖；
2. 脚本里出现硬编码参数 = 缺陷；
3. 跑批前做**等值校验**（模板参数 == spec），不是「不小于」。

**为什么**：我们遇到过参数在三个地方漂移（脚本默认、模板文件、命令行），结果「跑的不是定案配置」，一整轮白跑。

## 3. 目录职责

```
<PROJECT_ROOT>/
├── docs/                    # 方法论、分镜源文档、试错记录
│   ├── prompts/<act>/       # ★ 每镜一份，唯一源
│   └── trials/              # 事故记录
├── assets/
│   ├── characters/<role>/   # 多视角 + 特写
│   ├── envs/                # 场景
│   ├── voices/              # 音色参考
│   └── shots/<group>/       # 尾帧图 / 尾段视频
├── configs/
│   └── episodes.json        # 派生：镜头清单（由 md 生成，禁止手改）
├── code/                    # ★ 随包脚本（运行时放在 <PROJECT_ROOT>/code/）
├── output/                  # 产物（不入库）
└── preview/                 # 审片帧（不入库）
```

**源与派生的关系（重要）**：

```
docs/prompts/*.md  ──build──▶  configs/episodes.json  ──build──▶  生成模板
      (源)                          (派生)                        (派生)
```

派生产物永远不手改。改源 → 重建。手改派生 = 下次重建静默丢失。

## 4. 脚本职责表

| 脚本 | 职责 | 关键约束 |
|---|---|---|
| `build_episodes.py` | md → episodes.json | 源文档解析；支持只重建指定镜头 |
| `build_twopass.py` | episodes → 生成模板 | 参数全部从 spec 读 |
| `run_twopass_auto.py` | 跑批（抽卡/精修） | 前置校验：模板 vs spec、参考视频帧数、产物分辨率 |
| `relay.py` | 截尾帧 + 尾段视频 | 帧数 == spec；必须重编码；输出校验和 |
| `seam_join.py` | 两镜拼接 | 交叉淡化 == spec；同规格前置校验 |
| `join_clips.py` | 全片拼接 | 逐镜实测时长累加（禁用乘法） |
| `upscale_batch.py` | 逐镜超分 | 单输入直出；分批限内存 |
| `sync_assets.py` | 资产双份同步 | 项目份 → 生成端输入目录 |
| `quality_gate.py` | 首帧像素差门禁 | 双界阈值（优/及格/废） |
| `check_ref_desc.py` | 锁帧语义检查（**未随包**，缺失时显式跳过） | 视觉模型；结果只作中止条件之一 |
| `check_lockframe_desc.py` | 构图一致性检查 | 纯文本，零 GPU |
| `check_scene_chain.py` | 场景继承链检查 | 角色去向 / 环境状态 |
| `audio_check.py` | 削波检测 | 峰值 > 0dB 直接淘汰 |
| `card_selector.py` | 候选评分池（**未随包**） | 全局最优 + 打回换卡 |
| `chain_check.py` | 源一致性门禁 | md ↔ episodes ↔ 模板 三层摘要比对 |
| `auto_pipeline.py` | 全自动编排（**未随包**） | 状态机 + 断点续跑 + 审计日志 |

## 5. 一镜走查（顺畅路径）

```bash
# 0) 恢复报告：生效配置、当前批、产物存在性
python code/run_twopass_auto.py --status

# 1) 写/改镜头源文档
#    docs/prompts/<act>/<shot>.md
#    必须含：参考图列表、承接关系、场景状态继承、正文时间轴

# 2) 重建派生链（只重建本镜，避免影响其他镜头）
python code/build_episodes.py --shots <shot>
python code/build_twopass.py --shot <shot> [--video-ref <上一镜尾段>]

# 3) 抽卡（低分辨率，多份）
#    批配置里指定：镜头、轮数、种子域
python code/run_twopass_auto.py

# 4) 审片：抽固定时间点成图，人工+视觉模型过一遍
python code/relay.py --shot <shot> --preview

# 5) 选定候选 → 精修（高分辨率）
#    修改批配置指向选中的种子
python code/run_twopass_auto.py

# 6) 门禁：首帧像素差 + 语义检查 + 音频削波
python code/quality_gate.py <产物.mp4> --ref <上一镜尾帧.png>

# 7) 接力：截尾帧与尾段视频，供下一镜使用
python code/relay.py --shot <shot>

# 8) 拼接（相邻两镜）
python code/seam_join.py --a <shotA.mp4> --b <shotB.mp4>

# 9) 全片拼接 + 逐镜超分
python code/join_clips.py <clip...> --out <成片.mp4>
python code/upscale_batch.py --out <成片.mp4> --clips <镜...>
```

## 6. 门禁的三层实现

| 层 | 机制 | 拦什么 |
|---|---|---|
| **同步层** | 使用点自动重建 | 源文档改了但派生没重建 |
| **一致性层** | 派生摘要 vs 当前源；不一致 = 中止 | 手改派生物、旧模板残局 |
| **产物层** | 产物分辨率 == spec 交付值（未覆盖 sidecar 指纹与提交钩子） | 用旧配置产出的旧片子冒充新片（仅部分拦截） |

另外两件（sidecar 指纹、提交时钩子）在源项目里有，**未随包**——不要按本节假设它们存在。

**设计意图**：不依赖人的自觉。规则写在文档里，人一定会忘；写在代码里，忘不了。

## 7. 自动化编排（本包不含编排器）

状态机流水线：

```
接力 → 预处理(构建+六项检查) → 抽卡 → 审帧 → 选卡 → 精修 → 门禁 → 接力 → … → 拼接 → 超分
```

要点：
- **本包不含批次配置文件**：镜头选择通过 `run_twopass_auto.py` 顶部的 `RUNS` / `SHOT` 变量（注释标明为示例，使用前替换）；
- **断点续跑**：每个阶段先查产物存在性，存在即跳过；
- **幂等**：重复运行不产生重复产物；
- **审计日志**：每次决策一行 JSON，供事后复盘与告警；
- **人工暂停是一等状态**：暂停标记优先于任何自动恢复。

## 8. 已知限制

| 限制 | 说明 |
|---|---|
| 平台 | Windows 路径与编码有坑；Linux 未验证 |
| 显存 | 16GB 是下限，高分辨率精修会 OOM |
| 长镜 | 超过 10 秒需额外验证（尾段伪影风险） |
| 多人 | 超过 3 个主要角色同框，一致性快速下降 |
| 文字 | 画面中的中文文字基本不可靠 |
| 音频 | 精修链路的音量可能与抽卡不一致 |
| 自动选片 | 动态过程判断不可靠，必须人工终审 |

## 9. 换成别的技术栈怎么迁移

按这个顺序，每一步都可独立验证：

| 步骤 | 动作 | 验证 |
|---|---|---|
| 1 | 替换**生成模型**，先跑通单镜 | 能生成 5 秒、有声音、主体正确的片子 |
| 2 | 替换**提示词格式** | 保留六段职能，映射到新模型的输入结构 |
| 3 | 替换**参考图机制** | 找新的「锁帧」实现（首帧条件/关键帧/图生视频） |
| 4 | 替换**运动延续** | 若无视频参考，退化为锁帧 + 后处理 |
| 5 | 替换**精修** | 二次生成或纯超分，二选一，先定验收标准 |
| 6 | 保留**配置源 + 门禁 + 构建链** | 这套结构是技术无关的 |
| 7 | 重测所有**经验数值** | 帧数、阈值、拍数上限全部重标定 |

**不要做的事**：把旧栈的超参数照搬到新栈，然后解释为什么「新模型不行」。
